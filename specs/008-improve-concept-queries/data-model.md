# Data Model: Graph Concept Resolution

**Date**: 2026-02-28
**Feature**: 008-improve-concept-queries

## Entities

### CONCEPT_TO_CATEGORY (new, static mapping)

A static dictionary mapping concept slug patterns to TechCategory values.

| Field | Type | Description |
|-------|------|-------------|
| slug | str (key) | Concept slug as generated by planner (e.g., "machine-learning", "ml") |
| category | str (value) | TechCategory enum value (e.g., "ml_framework", "concept") |

**Identity**: slug (exact match, case-insensitive)
**Lifecycle**: Static, defined at module level. No runtime mutations.

### Mapping entries

| Concept | Slugs | → TechCategory |
|---------|-------|----------------|
| Machine Learning | `machine-learning`, `ml` | `ml_framework` |
| AI Agents | `ai-agents`, `ai-agent` | `concept` |
| RAG | `rag` | `concept` |
| Computer Vision | `computer-vision`, `cv` | `ml_framework` |
| NLP | `nlp` | `ml_framework` |

## Existing Entities (unchanged)

### GraphNode (TECHNOLOGY)
- Created from `Technology` table during graph build
- Has `slug`, `name`, `data.category` (TechCategory value)
- Found by `store.get_node_by_slug(entity_key)`

### GraphQueryResult
- Returned by all query functions
- Fields: `items`, `found`, `sources`, `confidence`, `intent`, `entity_key`
- No schema changes needed

## Data Flow

```
entity_key="machine-learning"
    ↓
get_node_by_slug("machine-learning") → None (not a technology node)
    ↓
partial project match → None (not a project)
    ↓
CONCEPT_TO_CATEGORY.get("machine-learning") → "ml_framework"  ← NEW
    ↓
_projects_by_tech_category_query("ml_framework") → GraphQueryResult with projects
```
